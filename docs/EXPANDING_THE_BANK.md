# Як розширювати банк питань за допомогою AI

Цей документ — інструкція для майбутньої сесії Codex. Попросіть Codex **внести зміни у файли проєкту**, а не просто запропонувати список питань. Наприклад: «Додай React до інтерв’ю за `docs/EXPANDING_THE_BANK.md`». Поки такого запиту немає, React не входить до поточної програми.

## Перед генерацією

1. Визначте тему, рівень, приблизний обсяг і частку в змішаному інтерв’ю. Для нової теми попросіть кілька підтем та типів завдань, а не десятки майже однакових визначень. Для розширення наявної теми назвіть прогалини, які потрібно закрити.
2. Нехай AI прочитає `AGENTS.md`, `docs/CURRICULUM.md`, `docs/QUESTION_FORMAT.md`, наявні файли `data/`, скрипти вибору/перевірки та поточні ID. Так він не повторить уже наявні питання й не зламає формат.
3. Попросіть перевірити актуальну офіційну документацію і додаткові джерела. Репозиторії з питаннями придатні як орієнтир тем, але формулювання, пояснення і приклади мають бути оригінальними. Збережіть корисні URL у `docs/SOURCES.md` та `source` кожного питання.

## Критерії для нового пакета

- Кожне питання перевіряє конкретне вміння на рівні Junior. Формулювання коротке й однозначне; правильна відповідь перевірена. Уникайте застарілих рекомендацій, тривіальних перефразувань одного питання та senior-рівня без окремого запиту.
- Змішуйте `open`, `mcq`, `output` (коли доречно), `debug` і `coding`. MCQ має чотири правдоподібні варіанти й одну чітко найкращу відповідь; розподіляйте правильні літери A–D. Для коду додавайте короткі приклади, обмеження, критерії приймання та крайові випадки. Не змушуйте створювати цілий застосунок для маленького завдання.
- Використовуйте стабільні нові ID, наприклад `react-hooks-001` і `code-react-001`. Не перейменовуйте ID, які могли потрапити до `progress/history.jsonl` або черги повторення. Перед записом перевірте збіги за змістом з існуючими питаннями, а не лише збіги ID.
- Заповнюйте приватні поля відповіді (`expectedPoints`, `correctOption`, `expectedOutput`, `evaluationNotes`, `hiddenTests`) для оцінювання, але не показуйте їх кандидату. Селектор має друкувати лише публічні поля.
- Якщо додаєте питання до **наявної** теми, змінюйте `scripts/build-bank.py` разом із відповідним JSON: повторний запуск цього генератора перезаписує початкові файли `data/questions/*.json` і `data/coding/*.json`. Для **нової** теми можна створити окремі JSON-файли вручну; поточний генератор їх не перезаписує. Після появи реальних відповідей ніколи не переставляйте рядки генератора так, щоб змінились старі ID.

## Якщо додається нова тема, наприклад React

Одних `data/questions/react.json` і `data/coding/react.json` недостатньо: скрипти мають фіксований список тем. Попросіть Codex виконати весь перелік:

1. Створити кураторський пакет React на Junior-рівні: компоненти, JSX, props/state, події, списки й keys, контрольовані форми, hooks (`useState`, `useEffect` і cleanup), передавання даних, Context на базовому рівні, завантаження даних і типові помилки. Додати невеликі практичні та debugging-завдання. Старі підходи позначати як такі, що трапляються в наявних кодових базах.
2. Додати JSON-файли до `data/questions/` і `data/coding/` за `docs/QUESTION_FORMAT.md`. Взяти теми з [React Learn](https://react.dev/learn), [React API Reference](https://react.dev/reference/react) та [DevLoversTeam React questions](https://github.com/DevLoversTeam/react-interview-questions), перевіряючи актуальність. Записати джерела у `docs/SOURCES.md`.
3. Додати `react` у `TOPICS` і `loadBank()` у `scripts/interview-state.mjs`; у список файлів `scripts/validate-bank.mjs`; у перевірку `--focus`, `--include`, `--exclude` та `weights` у `scripts/select-question.mjs`. Зберегти суми ваг 100% і роботу режиму focus (~75% теми). Приклад **лише для обговорення**: JS 35%, Angular 25%, React 20%, Node/Express 12%, HTML 4%, CSS 4%. Остаточну пропорцію визначає запит користувача.
4. Оновити `AGENTS.md`, `docs/CURRICULUM.md` і README: додати `focus react`, нову пропорцію та правила сучасного React. Прибрати чинну заборону React тільки тоді, коли користувач справді попросив додати його до програми.
5. Переконатися, що `scripts/record-answer.mjs`, статистика, review queue і вже збережені ID працюють із новою темою. **Не скидати і не переписувати `progress/`**. Не замінювати незавершене `current-session.json.pending`; нова тема стане доступною для наступного вибору питання.

Для іншої нової теми кроки ті самі, змінюються назва, навчальна програма, джерела і ваги.

## Перевірка перед завершенням

Запустіть `npm run validate` та `npm test`. Валідатор має підтвердити унікальність ID і всі поля схеми. Окремо перевірте правильність кількох нових відповідей/прикладів і те, що MCQ має одну чітку відповідь. Перевіряйте вибір нового питання **на тимчасовому стані**, задавши `INTERVIEW_STATE_DIR` на новий тимчасовий каталог; не запускайте `npm run next` на реальному `progress/` тільки для тесту. Спробуйте звичайний режим, `--focus react` і публічний вивід: у ньому не повинно бути відповіді чи прихованих тестів. Після перевірки видаліть лише створений вами тимчасовий каталог. Наприкінці повідомте кількість доданих питань і завдань, нові ваги, джерела та результати перевірок.

## Готовий запит для Codex

> Додай React до цього інтерв’ю-проєкту за `docs/EXPANDING_THE_BANK.md`. Рівень Junior, сучасний React. Створи приблизно 35–45 якісних питань і 8–12 коротких coding/debugging-завдань; не копіюй чужі відповіді дослівно. Зроби React близько 20% звичайного змішаного інтерв’ю та підтримай `focus react`. Перевір офіційні джерела, онови JSON, скрипти, AGENTS.md і документацію, запусти перевірки на тимчасовому стані. Збережи всі мої наявні результати й поточне незавершене питання.

Для іншої теми замініть назву, орієнтовний обсяг і бажану частку. Якщо хочете лише більше питань з JavaScript, скажіть, які підтеми слабко представлені, і попросіть доповнити наявний банк без додавання нового topic.
